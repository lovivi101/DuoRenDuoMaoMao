# 任务 T2：《熄灯》TS 服务器（初版可玩）

你是服务端工程师。工作目录：`E:\Game_Work\AI 游戏\多人躲猫猫\服务器端\TS_Server`（当前为空，从零搭建）。
必读：`文档/《熄灯》策划案.md`、`文档/01-策划分析与素材需求.md`（第 2 节 MVP 范围）、**`文档/02-网络协议.md`（契约，严格遵守）**。
不要动 `服务器端/Due_Server`（旧 Go 版，与本任务无关）、`客户端/`、`素材/`。

## 技术栈

- Node 22（本机 v22.20）+ TypeScript（strict），ESM。运行：`tsx`（开发）/ `tsc` 编译到 `dist`（生产）。
- HTTP：原生 `node:http` 或 `fastify`；WebSocket：`ws`。
- 存储：内置 `node:sqlite`（`DatabaseSync`），文件 `data/xideng.db`；封装 `Store` 接口，方便后续换 PostgreSQL。
- 密码：`crypto.scrypt` + 随机盐；token：HMAC-SHA256 签名的 JWT（可用 `jose` 或自实现），密钥来自 `.env`（提供 `.env.example`）。
- 测试：`vitest` 或 `node:test`，`npm test` 必须全部通过。

## 必须实现

1. **账号体系**：协议第 2 节全部接口。微信与短信在未配置时为 mock 模式（见协议）。短信 60s 冷却、验证码 5 分钟有效、错 5 次作废。游客可后续绑定（预留接口 `POST /api/bind/phone`、`/api/bind/wechat` 可选实现）。
2. **大厅**：WebSocket 鉴权、在线状态、快速匹配（按到达顺序凑 8 人即开，最多 12；等待 ≥60s `canAiFill=true`，`match.aiFill` 用 AI 补到 8 人开局；开发环境变量 `MATCH_MIN_PLAYERS` 可调小便于测试）、创建房间（6 位数字房间码唯一）、加入、离开、准备、房主设置/踢人/加 AI、开始、好友邀请、再来一局。房主离开自动移交。
3. **地图**：在 `src/game/maps/old_dorm.ts` 按策划案 8.2 做旧宿舍楼：64×40 格，中央大厅（猎手出生点 + 牢笼）、北区宿舍走廊（小房间多）、东区食堂、南区仓库（货架迷宫，绕圈结构）、西区澡堂（上锁安全屋）；外墙/承重墙 + 约 40% 可破坏隔断墙；每区至少 2 个出入口；3 台发电机分散；每区 2～3 个道具点（中央大厅无）；伪装物按区域主题摆放。提供 `npm run map:ascii` 打印 ASCII 地图方便审查。
4. **对局模拟（服务端权威，20Hz tick）**：
   - 阶段机：`assign` 5s → `hide` 20s（猎手锁在出生房间）→ `hunt` → 最后 30s `final` → `result` 15s → 房间回到 `waiting`。
   - 角色分配：8～9 人 1 猎手，10～12 人 2 猎手（`hunterCount` 可覆盖）；上局猎手本局不当；`moleEnabled` 且 ≥10 人时抽 1 卧底（初版只需身份与互相可见，报点为可选）。
   - 移动：走/跑速度、体力、与墙体网格碰撞（圆形碰撞体半径 0.35 格）；跑步产生脚印（3 秒）与 3 格波纹（节流，每 0.5s 一次）。
   - 视野过滤：按协议第 4 节防作弊规则，用网格射线（DDA/Bresenham）判断视线；猎手手电 60° 6 格扇形。
   - 伪装：在伪装物 2 格内可伪装成地图该区域存在的 prop；移动即解除（0.5s 动作）；伪装每 10s 发极小抖动 fx。
   - 拍打：1.2 格内自动吸附最近目标；打中藏者/伪装藏者 → 被抓送牢笼（变 `caged`，10s 内选幽灵阵营，客户端展示阵营选择，服务器把状态设为 `ghost`，但仍保留 `caged` 以便救援：用字段区分即可，务必在协议实现备注里写清楚）；打空或打错伪装物 → 猎手硬直 1.5s + 8 格红色波纹。
   - 救援：藏者在牢笼旁按住交互 3s，被救者恢复藏者；每人只能被救 1 次。
   - 发电机：按住交互修理，1 人 25s、2 人 15s、3 人 10s；修理中每 1s 冒 8 格波纹；修好后剩余时间 -60s。
   - 道具：开局 6 个道具点预置；追捕期每 60s 掉落 3～4 个（提前 5s `game.drop` warn）；拾取上限 2；实现初版 8 个道具（协议第 5 节），拾到对方阵营道具转为本阵营同品质道具。
   - 周期事件：追捕期每 60s，提前 5s warn；初版 4 个事件（协议第 5 节），同一事件一局最多 2 次；存活率失衡权重调整。
   - 可破坏墙：`wall_cracked` 可被猎手连续拍打 3 次打破（初版简化，替代破墙锤）→ 变 `rubble`，广播 `game.wall` 与 8 格波纹。
   - 最终 30s：猎手移速 +20%，所有藏者每 2s 心跳波纹。
   - 幽灵：守护灵 30s 冷却在指定位置制造假波纹；怨灵 30s 冷却标记一名藏者 2s（猎手可见）。
   - 胜负与计分：策划案第 7 节全表；MVP 双阵营；奖励写回用户（经验、金币、段位分）。
   - 断线：30s 内重连回到对局（`hello.reconnect`）；超时藏者按被抓处理；猎手全掉线本局作废。
5. **AI 机器人（很重要，客户端单人测试全靠它）**：藏者 AI 会找伪装点伪装、听到附近猎手波纹会跑开、会去修发电机、会捡道具；猎手 AI 会巡逻、追最近的波纹/脚印、看到藏者追击并拍打、会拍可疑伪装物（有一定失误率）。AI 走格子寻路（A*）。
6. **工具脚本**：`npm run dev`（热重载）、`npm run build`、`npm start`、`npm test`、`npm run sim`：**无头模拟一整局**（全 AI，加速时间），打印阶段、抓捕、发电机、事件、胜负与得分，作为端到端自检。`npm run bots -- --room <code> --n 3`：用真实 WS 协议连接的测试机器人客户端（给客户端联调用）。

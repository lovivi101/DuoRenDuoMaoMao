# 《熄灯》客户端 ↔ TS 服务器 协议（初版契约）

> 本文由统筹方起草，服务器实现方（T2）可在「实现备注」里补充细节，但**不得改动消息名与已有字段含义**。客户端（T4）严格按本文实现。

## 0. 约定

- 服务器：Node 22 + TypeScript，默认端口 **8787**。HTTP 前缀 `/api`，WebSocket 路径 `/ws`。
- 所有消息 JSON UTF-8。WebSocket 消息统一形如 `{"t":"<type>", ...fields}`。
- 鉴权：HTTP 用 `Authorization: Bearer <token>`；WebSocket 用 `ws://host:8787/ws?token=<token>`。
- 错误：HTTP 返回 `{ "ok": false, "code": "SMS_CODE_WRONG", "msg": "验证码错误" }`；成功返回 `{ "ok": true, ... }`。WS 错误用 `{"t":"error","code","msg"}`。
- 坐标单位：**格**（1 格 = 32 像素），浮点；地图原点左上角，x 向右 y 向下。
- 时间：服务器时间戳毫秒 `serverNow`，客户端据 `hello.serverNow` 求时钟差。

## 1. 用户对象

```json
{ "id": "u_xxx", "shortId": "10238471", "nickname": "小夜猫", "color": "blue",
  "level": 3, "exp": 120, "coins": 560, "gems": 20, "rankScore": 1000,
  "needsProfile": false, "bindings": { "wechat": true, "phone": "138****0000", "account": null } }
```

`color` ∈ `red|orange|yellow|green|cyan|blue|purple|pink`。`needsProfile=true` 表示首次进入，客户端跳「创建角色」。

## 2. HTTP 接口

| 方法 路径 | 请求 | 响应 |
| --- | --- | --- |
| `POST /api/auth/wechat` | `{ code }` 微信 SDK 授权码 | `{ ok, token, user, isNew }` |
| `POST /api/auth/sms/send` | `{ phone }` 11 位大陆手机号 | `{ ok, cooldown: 60, devCode? }`（仅开发模式回传 `devCode`） |
| `POST /api/auth/sms/login` | `{ phone, code }` | `{ ok, token, user, isNew }` |
| `POST /api/auth/register` | `{ account, password }` 账号 4-20 位字母数字下划线，密码 6-32 位 | `{ ok, token, user, isNew:true }` |
| `POST /api/auth/password` | `{ account, password }` | `{ ok, token, user, isNew:false }` |
| `POST /api/auth/guest` | `{ deviceId }` | `{ ok, token, user, isNew }` |
| `GET /api/me` | — | `{ ok, user }` |
| `POST /api/profile` | `{ nickname, color }` 昵称 2-12 字 | `{ ok, user }` |
| `GET /api/profile/random-name` | — | `{ ok, nickname }` |
| `GET /api/friends` | — | `{ ok, friends: [{ user, status: "online"|"in_game"|"offline" }] }` |
| `POST /api/friends/add` | `{ shortId }` | `{ ok, friend }` |
| `GET /api/notice` | — | `{ ok, notices: [{ title, body }] , version }` |

微信登录：环境变量 `WX_APPID`/`WX_SECRET` 存在时走真实 `sns/oauth2/access_token` 换 openid；否则为 **mock 模式**，任意 `code` 以 `mock_` 开头即视为 openid=`code`。短信：未配置短信服务商时为 mock，验证码打印到服务器日志并在 `devCode` 返回。错误码：`PHONE_INVALID`、`SMS_TOO_FREQUENT`、`SMS_CODE_WRONG`、`ACCOUNT_EXISTS`、`ACCOUNT_INVALID`、`PASSWORD_WRONG`、`NICKNAME_INVALID`、`UNAUTHORIZED`、`NOT_FOUND`。

| `room.leave` | — | |

| `room.settings` | `settings` | 仅房主，等待阶段 |
| `room.addBot` / `room.kick` | `playerId`（kick） | 仅房主 |
| `room.start` | — | 仅房主；人数不足且 `aiFill` 时自动补 AI |
| `room.invite` | `friendId` | 好友收到 `invite {from, code}` |
| `vote.cast` | `mapId` | |

## 4. WebSocket：对局

对局阶段 `phase`：`assign`(5s) → `hide`(20s) → `hunt` → `final`(最后 30s) → `result`(15s)。

服务器 → 客户端

| t | 字段 |
| --- | --- |
| `game.start` | `mapId, map, you: { id, role }, allies: [{ id, role }]`（猎手与卧底互相可见）, `players: [{ id, nickname, color, isBot }]`, `durationSec` |
| `game.phase` | `phase, endsAt` |
| `game.snap`（20Hz） | 见下 |
| `game.event` | `kind, stage: "warn"\|"start"\|"end", at, durationSec` |
| `game.wall` | `cells: [{ x, y, tile }]`（墙体变化） |
| `game.drop` | `drops: [{ id, x, y, stage: "warn"\|"landed"\|"taken" }]` |
| `game.caught` | `hunterId, victimId, x, y` |
| `game.rescued` | `rescuerId, victimId` |
| `game.fx` | `kind, x, y, by?`（如 `slap_miss`、`smoke`、`banana_slip`、`generator_fixed`） |
| `game.result` | `winner: "hider"\|"hunter", players: [{ id, nickname, color, role, score, breakdown: [{ label, pts }], caught }], mvp: { hider, hunter }, rewards: { exp, coins, rankDelta } }` |

`game.snap`：

```json
{ "t":"game.snap", "tick": 1234, "now": 1727000000000, "timeLeftSec": 402.5,
  "alive": 7, "totalHiders": 9, "caughtByMe": 0,
  "you": { "x": 10.5, "y": 8.2, "dir": 1.57, "state": "normal|disguised|ghost|caged|stunned",
           "stamina": 3.2, "items": ["smoke", null], "prop": null, "flashlight": true,
           "visionRadius": 5, "ghostSide": null, "cooldowns": { "ghostSkill": 0, "report": 0 },
           "progress": { "kind": "repair|rescue|accuse", "value": 0.4 } },
  "players": [ { "id": "u_2", "x": 12, "y": 9, "dir": 0, "state": "normal|disguised|ghost|caged|stunned", "prop": "cardboard_box", "running": true } ],
  "ripples": [ { "x": 20, "y": 14, "r": 3, "kind": "run|door|box|repair|crash|wall|heartbeat|fake", "hunter": false } ],
  "footprints": [ { "x": 11.2, "y": 8.9, "dir": 1.2 } ],
  "generators": [ { "id": 0, "x": 5, "y": 30, "progress": 0.35, "fixed": false } ],
  "marks": [ { "x": 15, "y": 20, "kind": "danger|help|item|suspect|report|wraith", "until": 1727000003000 } ] }
```

**防作弊**：`players` 只包含对你可见的玩家（光圈半径内 + 视线未被墙遮挡，猎手另加手电扇形）；伪装中的藏者只下发 `state:"disguised", prop`；幽灵对猎手不可见；视野外只下发 `ripples`。

客户端 → 服务器

| t | 字段 | 说明 |
| --- | --- | --- |
| `game.input` | `seq, mx, my, run` | 摇杆向量（-1..1），`run`=推到外圈；变化时发送且至少 10Hz |
| `game.action` | `kind`, 可选 `slot, prop, dx, dy, x, y, targetId` | `kind` ∈ `slap`、`interact_start`、`interact_stop`、`disguise`、`undisguise`、`flashlight`、`use_item`、`accuse_start`、`accuse_stop`、`report`、`ghost_skill` |
| `game.ghostSide` | `side: "guardian"\|"wraith"` | 被抓后 10 秒内选择，超时默认守护灵 |
| `game.mark` | `kind, x, y` | 快捷标记 |

## 5. 地图数据（`map`）

```json
{ "id": "old_dorm", "w": 64, "h": 40, "tileSize": 32,
  "tiles": "<base64 of w*h bytes>", 
  "legend": { "0": "floor", "1": "wall_solid", "2": "wall_cracked", "3": "door", "4": "rubble", "5": "void" },
  "zones": [ { "name": "中央大厅", "x": 26, "y": 14, "w": 12, "h": 12, "floor": "tile" } ],
  "hunterSpawn": { "x": 32, "y": 20 }, "cage": { "x": 32, "y": 17 },
  "hiderSpawns": [ { "x": 30, "y": 22 } ], "generators": [ { "id": 0, "x": 8, "y": 6 } ],
  "itemSpots": [ { "x": 10, "y": 10 } ],
  "props": [ { "x": 12, "y": 5, "prop": "cardboard_box" } ] }
```

伪装物 `prop` ∈ `cardboard_box|chair|potted_plant|pillow|desk_lamp|trash_can|oil_drum|food_tray`。
初版道具 `items`：猎手 `strong_flashlight|net|bell_trap|sprint_shoes`；藏者 `smoke|banana|speed_shoes|wood_board`（其余预留）。
初版周期事件：`blackout|emergency_light|adrenaline|broadcast`（其余预留）。

### T2 实现备注（追加）

- 密码使用 `crypto.scryptSync`（随机 16 字节盐）；token 为 HS256 风格三段 JWT，签名密钥来自 `JWT_SECRET`。开发环境微信仅接受 `mock_` 前缀授权码，短信响应附带 `devCode`；短信验证码 60 秒冷却、5 分钟过期、连续错误 5 次作废。
- Store 暴露 `getUser/findAccount/findPhone/findWechat/saveUser/listUsers` 接口，默认使用 `data/xideng.db` 的 `node:sqlite`，无法加载内置模块时自动退回进程内实现，便于测试与后续替换 PostgreSQL。
- WS 服务端每 50ms 推送 `game.snap`，所有移动、墙体碰撞、视野、拍打、伪装、发电机、事件和结算均由服务端判定。`players` 按观察者附近范围和墙体 DDA 视线过滤；猎手额外应用 60°、6 格手电扇形。
- 被拍打后玩家的 `state` 设为 `caged`，并保留 `caught=true`；在 10 秒内选择 `game.ghostSide` 后增加 `ghostSide`（`guardian`/`wraith`），客户端仍收到 `state:"caged"` 以便牢笼救援流程继续使用。幽灵不可被猎手普通视野看到。
- `room.start` 在 `aiFill=true` 且人数不足时补 AI 至 `MATCH_MIN_PLAYERS`（默认 8）；`MATCH_MIN_PLAYERS` 可在开发环境调小。房主离开时自动移交给最早在线玩家。
- 初版地图 `old_dorm` 为 64×40 网格，墙体图例与协议一致；`npm run map:ascii` 可审查墙体。道具、周期事件和掉落均使用协议第 5 节的枚举，掉落内容在拾取前不下发。

### T2 最终实现备注（只追加）

- 最终实现使用 `SqliteStore` 与 Node 22 `node:sqlite` `DatabaseSync`，`Store` 接口可替换；奖励表以 `(match_id,user_id)` 去重，避免断线/重复结算重复发奖励。若将 Node 22.20 运行在实验性 SQLite 开关环境，按 Node 运行时要求加 `--experimental-sqlite`。
- 地图序列化仍使用协议 `map.tiles` 字段，服务器向 WS 发送 base64；服务端内部是每个房间独立的 `Uint8Array`，破墙三次只改变该对局。旧宿舍楼 64×40，四区出入口、中央牢笼、3 台发电机、12 个道具点、每区至少 2 个伪装物。
- `game.input` 的 `seq/mx/my/run` 会在服务器校验后写入输入状态，20Hz tick 每次最多按 50ms 积分；旧包、非有限数、越界向量和超过 100 条/秒的 WS 消息会被拒绝或限流。
- `game.snap` 的 `players` 经过 DDA 墙体遮挡、个人视野半径和猎手手电 60°/6 格过滤；视野外只保留 `ripples`、脚印和本阵营标记。伪装目标只在服务器确认同区域真实 prop 且距伪装点 2 格以内时成立，移动会解除并执行 0.5 秒动作。
- 被抓玩家 `caged=true,caught=true,state:"caged"`，10 秒内可发 `game.ghostSide`，选择后 `state:"ghost"` 但仍保留 `caged=true`，因此救援仍可进行；幽灵技能冷却 30 秒。猎手全部断线超过 30 秒时对局作废，藏者断线超过 30 秒按被抓处理，30 秒内带同一 token 重连会收到 `hello.reconnect`。
- 周期事件提前 5 秒发 `game.event warn`，开始/结束分别发 `start/end`；同一事件一局最多 2 次。道具掉落提前 5 秒只公布位置和阶段，拾取前不公布内容；对方阵营道具由服务器按同品质转换。
- `game.result` 包含双方 MVP、个人 breakdown 与奖励；奖励写回 SQLite 且幂等。`room.again` 在结算阶段将房间复位为 waiting。

### T2 实现备注（行为修正追加）

- 开发环境 `MATCH_MIN_PLAYERS` 最低可设为 `1`，便于单客户端进入匹配；若房间开启 `aiFill`，开局仍补足到 8 个席位，保证角色分配、AI 行为和完整对局可测试。生产环境固定匹配门槛为 8 人。
- `room.again` 在 `result` 阶段由任一房间成员触发后立即清理上一局状态并广播 `room.state phase:"waiting"`；机器人席位保留为已准备，真人重新准备后可再次开始。
- `.env.example` 提供满足 HS256 最小长度校验的开发密钥占位符；部署时必须替换为随机密钥。

### T2c 实现备注（追加）

- 旧宿舍楼地图 `legend` 在既有 0～5 后追加 `"6":"furniture"` 与 `"7":"shelf"`。两者都阻挡移动；`furniture` 不挡视线，`shelf` 挡视线。客户端可直接按 `map.legend` 渲染。地图包含 64 个 `props`，覆盖第 5 节全部 8 种 `prop` 值；原有协议消息名、字段与含义不变。
- 发电机修好会缩短当前追捕截止时间，服务器因此再次发送 `game.phase`，其 `phase` 不变，仅 `endsAt` 更新。客户端应按新的截止时间刷新倒计时；这不是第二次进入追捕阶段。
- 可选开发环境变量 `DEV_HUNT_SEC`、`DEV_HIDE_SEC`、`DEV_ASSIGN_SEC`、`DEV_RESULT_SEC`、`DEV_VOTE_SEC` 分别覆盖追捕、躲藏、分配、结算和投票秒数。未设置时沿用原值，生产环境忽略这些覆盖。`MATCH_MIN_PLAYERS` 维持原行为。
- 发电机缩时改为「追捕时长 × 10%」：默认 600 秒局每台减 60 秒（与策划一致），300/480 秒局减 30/48 秒；客户端只需按 `game.phase` 的新 `endsAt` 刷新计时器，无需自行计算。房间默认 `durationSec` 为 600。
- `game.snap` 追加 `roster: [{ color, caught }]`（所有非猎手玩家，含卧底，按座位顺序；HUD 存活头像行用）与 `nextEventAt`（下一次随机事件预警的服务器毫秒时间，HUD「下次事件」倒计时用）。
- 地图数据追加两项纯视觉字段，不影响移动与视线：`furniture: [{ x, y, w, h, kind }]`（家具贴图覆盖的阻挡格，左上角格坐标 + 占格宽高；`bunk_bed`、`dining_table`）与 `decor: [{ x, y, kind }]`（地面装饰，左上角格坐标；`rug_dorm` 3×2、`puddle`/`bath_mat` 2×1，其余 1×1）。
